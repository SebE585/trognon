# S5L8920 memory map (stabilised reference)

Working reference, not a narrative: base addresses only, one row per block, no test
story. For how each value was obtained, what is proven versus still open, and the full
reasoning, see the narrative page: [3. Hardware map](../en/03-hardware-map.md) (and its
French mirror, [Carte matérielle](../fr/03-hardware-map.md)). This page exists so a base
address can be looked up without reading the narrative; it does not replace it.

Evidence level per block is the narrative page's own tag (DEVICE, SOURCE, mixed
DEVICE/HYPOTHESIS) — repeated here for a quick scan, not re-argued.

| Block | Base | Size | Status |
|---|---|---|---|
| CPU/MMU | — (CP15) | — | DEVICE |
| Display controller (CLCD) | `0x85400000` | — | DEVICE |
| Framebuffer | `0x4fd00000` | 320x480, RGB888 | DEVICE |
| GPIO | `0x83000000` | — | DEVICE, partial |
| GPIO interrupt controller (`GPIOIC`) | `0x39A00000` | — | not read — dropped the USB link once, treat as dangerous |
| VIC0 | `0xBF200000` | — | DEVICE |
| VIC1 | `0xBF210000` | — | DEVICE |
| VIC2 | `0xBF220000` | — | DEVICE |
| Timer block | `0xBF100000` | — | DEVICE |
| NAND bus 0 (`H2FMI0`) | `0x81200000` | — | DEVICE |
| NAND bus 1 (`H2FMI1`) | `0x81300000` | — | SOURCE, not swept |
| Wi-Fi/SDIO | `0x80000000` | `0x1000` | mixed DEVICE/HYPOTHESIS |
| IOP coprocessor register window | `0x86300000` | — | DEVICE: MMU descriptor confirmed mapped, register window read all-zero (a clock-gate read of `0xF` once attributed to the IOP belongs to the NAND controller 1 and is withdrawn); whether the IOP itself is running/accessible under iBSS is open |
| I2C bus 0 (`i2c0`, soft/bit-banged via GPIO) | `0x83200000`\* | `0x1000` | DEVICE on the accelerometer transaction (bit-banged over GPIO `04.00`/`04.01`, not through this MMIO window); the `0x83200000` register window itself is SOURCE, not probed |
| I2C bus 1 (`i2c2`, soft/bit-banged) | `0x83400000` | `0x1000` | SOURCE (device tree only, not yet probed) |

\* This bus is software/bit-banged (`compatible = "iic,soft"`): the confirmed accelerometer
read drove the GPIO pins directly and never touched the `0x83200000` MMIO window, so that
address stays a device-tree fact only.

Addresses for blocks not yet probed on the device (I2C bus 1, NAND bus 1, the i2c0 MMIO
window itself) come from this device's own decrypted device tree, the same provenance
already used for the Wi-Fi/SDIO block on the narrative page — see that page's caveat on
what DEVICE does and does not mean for a device-tree-sourced fact.

## Payload memory contract

Fixed addresses every payload in `tools/payloads/` relies on. Defined once here; the
narrative page ([2. Exception console](../en/02-exception-console.md)) explains why each
one was picked.

| What | Address | Notes |
|---|---|---|
| Payload code | `0x41000000` | Thumb, loaded by `send_data` |
| Scratch struct | `0x41080000` | not zeroed: RAM keeps the previous payload's values |
| Handler stack top | `0x410f8000` | own stack for exception modes |
| Framebuffer | `0x4fd00000` | 320x480, RGB888 `0x00RRGGBB`, mapped cacheable write-back |
| Vector page | VA `0x0` | = iBSS image `0x84000000` |

This reference is English-only (a technical lookup table, not project narrative); the
project's bilingual commitment applies to the narrative pages in `docs/en/`/`docs/fr/`
that explain and justify these values.
